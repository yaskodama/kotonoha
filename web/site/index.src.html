ことのは

日本語の文章で書く、アクター型の並列プログラミング言語

プログラムを日本語の文章として書きます。同じプログラムは、字下げで構造を示す構造化形式にも書けて、二つの書き方は機械的に行き来できます。

特徴

自然な日本語に見えて、読み方はひと通りにしか決まらない──そのための言語設計です。

文

文章がそのままプログラム

字下げも括弧も使いません。「〜を受け取ったとき、」「〜ならば、」「〜を送る。」といった日本語の言い回しで構造を表します。

ア

アクターとメッセージ

処理の単位は独立したアクター。状態を共有せず、メッセージを送り合って協調します。このページの中で実際に動かせます。

⇅

二つの書き方を行き来

文章形式と、字下げで構造を示す構造化形式。どちらで書いても同じ構文木になり、片方からもう片方を機械的に作れます。

一

一文方式

「〜ならば、」の本体はその一文だけ。二文以上は「次のことを行う。…以上。」で囲みます。これで日本語の曖昧さを文法から締め出します。

0

衝突 0 の LR(1) 文法

文法は bison で検査済み。衝突は 0 件で、正しい文章なら読み方は必ずひと通りに決まります（全 90 規則）。

名

名前は宣言から切り出す

日本語には空白がないので、宣言された名前（「先のフォーク」など）と予約語を、長いものから優先して切り出します。

二つの書き方

5 人の哲学者問題の「フォーク」アクターを、二つの形式で並べました。左を解析すると右が得られ、右を逆変換すると左に戻ります。

文章形式（インデントなし）

フォークというアクターを定義する。
フォークは番号と使用中と待ち行列を持つ。
番号の初期値は0とし、使用中の初期値はいいえとし、待ち行列の初期値は空とする。

フォークが「取りたい」というメッセージと哲学者を受け取ったとき、使用中がいいえならば、使用中をはいに変更し、哲学者に「渡す」というメッセージを送る。そうでなければ、哲学者を待ち行列の末尾に追加する。

フォークが「返す」というメッセージを受け取ったとき、待ち行列が空でなければ、待ち行列の先頭から次の哲学者を取り出し、次の哲学者に「渡す」というメッセージを送る。そうでなければ、使用中をいいえに変更する。

これでフォークの定義を終わる。

構造化形式（インデントあり）

「フォーク」というアクターを定義する。
    状態は 番号、使用中、待ち行列。
    初期状態は
        番号 は 0。
        使用中 は いいえ。
        待ち行列 は 空。
    以上。
    「取りたい」と 哲学者 を受け取ったとき、

            使用中 は はい。
            哲学者 に「渡す」を送る。
        そうでなければ、
            待ち行列 に 哲学者 を追加する。
        以上。
    以上。

定義を終わる。

哲学者は、番号の小さいフォークから先に取ります。そのため哲学者5だけはフォーク1を先に取り、全員が片方のフォークを握って待ち合う輪ができません（デッドロックしない）。フォークもアクターなので、隣り合わない哲学者は同時に食事できます。全文は「試してみる」の見本で読めます。

試してみる

サーバは使いません。このページに入っている解析器・逆変換器・実行系が、ブラウザの中で変換し、実行します。どちらの欄も書き換えられます。

⌘ / Ctrl + Enter で、カーソルのある欄から反対側へ変換
文章形式（インデントなし）
構造化形式（インデントあり）

逆変換で戻ってくるのは標準の書き方です。「その哲学者」の「その」や、文をどこで「。」で切ったかは構文木に残らないので、元の言い回しとは少し違うことがあります。構造化形式のほうは、往復しても一字も変わりません。
実行は、文章形式の欄のプログラムを構文木にして解釈します。アクターはそれぞれ受信箱を持ち、届いたメッセージを一通ずつ処理します。どのアクターが次に動くかは「動く順」で選びます。「ばらばら」は種つきの乱数なので、同じ種なら何度でも同じ動きを再現できます。種を変えると、並列ならではの別の動きになります。

文法

文章形式の文法は、文脈自由文法（BNF）で書けます。インデントを使わないので、Python のような字下げの扱いも要りません。

  • 文は「。」で終わる。一つの文の中では、動作を連用形（「変更し、」）でつなぎ、終止形（「送る。」）で閉じる。
  • 一文方式：「〜ならば、」「そうでなければ、」「〜について、」の本体は、その一文だけ。二文以上は「次のことを行う。 … 以上。」で囲む。
  • 条件の入れ子は「次のことを行う。」の中に書く。こうすると「そうでなければ」がどの「ならば」に付くか迷う余地がない。
  • 受信節（「〜を受け取ったとき、」）の本体は、次の受信節か「これで〜の定義を終わる。」まで。
  • 計算は括弧で囲む：「（AにBを加えた数）」「（AからBを引いた数）」「（AをBで割った余り）」。配列の長さは「列の要素数」、要素は「列の（現在の番号）番目」で、要素にも値を設定できる。
  • 繰り返しの範囲には式が書ける（「1から（列の要素数から1を引いた数）までの各番号について、」）。範囲は入る前に一度だけ計算するので、入れ子の内側の範囲には外側の「現在の番号」が使える。
  • 名前はアクター名・状態・受信の引数・「〜と名付ける」「〜を取り出す」で導入され、字句解析は予約語と宣言済みの名前を最長一致で切り出す。

「次のことを行う。」で囲まずに条件を直接入れ子にできる版も作りました。この版は if‑then‑else の衝突がちょうど 1 件出ます。C 言語と同じく「一番近い『ならば』に付く」と決めれば、読み方はひと通りに決まります。この版は、文章の読み手がそう読むとは限らないので、標準にはしていません。
